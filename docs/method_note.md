# ALIEN Method Note

ALIEN builds gene-set GMT files when source libraries and analysis namespaces do not line up cleanly. Source collections often mix current symbols, retired symbols, aliases, source Ensembl IDs, and occasional non-gene tokens. Downstream workflows, meanwhile, may require a specific target annotation release.

ALIEN treats integration as an audited projection problem. Every input source is normalized into one membership table, mapped through deterministic human gene resources, filtered, deduplicated, and written with QC records that explain what happened.

## Design

ALIEN accepts these source styles:

- Managed MSigDB release archives through the Python `msigdb_remote` reader.
- Managed Enrichr libraries through the Python `enrichr_remote` reader.
- Local MSigDB-like tables with symbols and additional source identifiers.
- Symbol-only GMT libraries, including local Enrichr-style exports.
- Tables already in ALIEN's canonical membership layout, and source types provided by other packages through the `alien.sources` entry-point group.

The builder creates a current-symbol namespace for display/review and any number of configured target namespaces. The implemented target adapter is `ensembl_gtf`: each target separates the output gene set from the annotation helper. By default, one Ensembl-style annotation GTF provides both; with `output_genes`, a dataset file/list defines the final output gene namespace and the GTF is primarily a symbol/metadata helper; with `gene_filter`, the final namespace is the intersection of annotation IDs and configured filter IDs. The GTF can come from GENCODE by version or from another annotation origin via a local path or URL, as long as gene ID and symbol attributes are present or mapped in config. In `output_genes`, `id_column` must contain Ensembl IDs; `symbol_column` is optional helper metadata for output genes absent from the GTF.

For dataset-specific output namespaces, the primary annotation can receive metadata fallbacks without being replaced. `annotation.metadata_fallbacks` loads a secondary GTF, adds only output IDs missing from the primary annotation, and records those rows as fallback metadata. When the same symbol is present in both primary and fallback annotations, the primary annotation remains the preferred mapping candidate. This keeps official releases such as GENCODE as the mapping authority while allowing resources such as recount3 to explain measured IDs absent from the official release file.

## Auditing

Each distinct (symbol, source Ensembl ID, NCBI-allowed) combination is resolved once per target by a fixed decision chain: configured non-gene tokens are dropped; a source Ensembl ID already in the target is kept; a retired source Ensembl ID with exactly one archive replacement in the target is rescued; otherwise the symbol is resolved through HGNC (exact current symbol, then manual repairs, legacy mitochondrial-genome names such as `ND1` or `TRNK` mapped to their `MT-` genes, previous symbols and aliases, with ambiguous previous symbols and aliases dropped and, for text-mined sources, alias-only matches shorter than `min_alias_length` rejected; a symbol none of these match is looked up once more ignoring letter case and, when exactly one gene matches, mapped with the status `hgnc_case_insensitive_symbol`; gene names a spreadsheet turned into dates, such as `1-Sep`, are repaired last), its annotation candidates are ranked (output genes first, then the primary annotation over fallbacks, then a unique protein-coding gene), the official HGNC Ensembl ID breaks remaining ties, a `LOC<GeneID>` token is resolved through the NCBI Gene ID it encodes, and NCBI Gene symbol rescue is tried last. Every member mapped by anything other than a source Ensembl ID or an exact current symbol is listed once per token in `metadata/symbol_rescues.tsv.gz`. Mapping uses HGNC current, previous, and alias symbols first. By default, source Ensembl IDs that are absent from the target annotation, any configured target output genes/filter, and HGNC's current Ensembl IDs are checked against the Ensembl archive cache. NCBI Gene history/info rescue is also enabled by default, but restricted to configured legacy source tags. Both fallback layers can be disabled in config. Ambiguous mappings are not guessed; they are written to audit tables.

Before mapping, ALIEN checks that each `term_id` refers to one source-term identity. Merging two source terms under one identifier would silently union their genes while one term's metadata wins, so by default the colliding identities are kept apart: the first keeps the ID and each other one gets a stable hash suffix. `metadata/term_id_collisions.tsv` records every case; the build can instead be configured to stop or to merge.

Filtering records dropped non-gene tokens, curated name exclusions (`filtering.exclude_terms`: for example KEGG MEDICUS mutant-variant and pathogen copies of reference pathways, pathways named after one pathogen, HPO onset and inheritance modifiers, and animal-model disease terms), broad disease categories, size-filtered terms, and redundancy removals; each excluded term names the rule that removed it. Redundancy filtering first collapses exact duplicate memberships, then clusters terms whose Jaccard similarity is above the configured cutoff within each namespace and family. Comparisons use Jaccard similarity strictly greater than the cutoff. A representative term is chosen by source priority first (unlisted sources last), then larger mapped size, then names that do not start with a generic prefix such as "regulation of", then the shorter name, then the term ID. By default clusters use single linkage (similar terms are joined transitively, so a chain A~B~C becomes one cluster); `redundancy.linkage: representative` instead removes a term only when it is above the cutoff against an already kept, better-ranked term. Candidate pairs come from a prefix-filter similarity join: genes are ranked from rarest to most common, and two terms can only exceed the cutoff if they share a gene among the first |S| - ceil(t|S|) + 1 genes of each, so ubiquitous genes no longer make the comparison quadratic. The result is identical to comparing every pair.

Source priority is configured per term family because different biological domains have different preferred authorities. For example, pathway outputs can prefer Reactome over broader ontology-derived terms, while disease outputs can prefer curated disease sources over noisier text-mined libraries. Priority only decides between redundant alternatives; it does not remove non-overlapping terms from lower-priority sources.

The primary GMT output is intentionally simple: one combined GMT per namespace. The surrounding metadata explains how each term reached that output.

## Reproducibility

ALIEN writes a compact source manifest, source provenance, package versions, target coverage summaries, mapping summaries, and warning logs. Provenance is assembled from what the build actually read: the ALIEN version, every package version, the sha256 of the effective configuration and of every input file, and every remote resource with its URL, hash and upstream version. `alien fetch` pins remote resources in `alien.lock.json`, and `alien build --frozen` reproduces a build from that lock without network access. Outputs are byte-for-byte reproducible apart from the provenance timestamp, which honours `SOURCE_DATE_EPOCH`; each output directory carries a `MANIFEST.json` that `alien verify` checks. `metadata/source_manifest.tsv` is the main article/protocol record for exact source collections: it lists each resolved source collection once, with term/member counts and Enrichr exact/regex resolution details when relevant. `metadata/target_metadata_fallbacks.tsv` records any secondary annotation files used to add metadata for missing output IDs. Enabled sources are required; missing source libraries stop the build rather than silently weakening the output. The source cache remains outside the package so license-sensitive resources can be managed by each user.

## Cache And Performance

Managed downloads are treated as reproducible source artifacts, while ALIEN keeps its own derived caches for repeated builds. MSigDB remote releases are checksum-verified and unpacked from the configured release archive; each RDS collection file is parsed once (cached by its sha256) and the matching rows are normalized into Parquet membership caches. Parsed GENCODE gene tables are cached by GTF sha256, and NCBI Gene rescue maps are stored in a prepared form keyed by the input hashes.

Large builds reuse those derived caches unless `--force-download` or source-level `force: true` is requested. Mapping resolves each distinct key once per target and joins the outcomes back to memberships, so it needs no process pool. Redundancy filtering runs per (namespace, family) group, in parallel when workers are available, using the prefix-filter join and union-find clustering. These optimizations are intended to change runtime, not output semantics; audit tables and GMT outputs remain deterministic for the same inputs and configuration.

## Limitations

ALIEN is scoped to human gene-set integration with HGNC symbols, MSigDB and Enrichr local/remote caches, optimized repeated-build caches, and Ensembl-style target namespaces. Non-Ensembl target ID systems, such as Entrez or UniProt GMT output, are future target adapters.
